The brief 25 Aug

Why build a self-hosted replacement for Appsero

From DEPLOY.md and packages/digi-tracker-client/README.md, the platform had to receive Appsero-protocol telemetry on infrastructure owned by PluginizeLab while meeting five constraints:

  • Permanent ingest paths: /track, /deactivate and /tracking-skipped are compiled into every released plugin copy and can never be changed once shipped.
  • WordPress.org Guideline 7 compliance: telemetry is strictly opt-in. The consent notice names Digi Tracker and links to our privacy policy, and the deactivation survey only fires when consent was granted.
  • No third-party IP lookups: upstream appsero/client queries icanhazip.com on every heartbeat. The fork removes that outbound call and derives country on our receiving server.
  • Encrypted contact details at rest: admin emails and names are encrypted with APP_KEY, paired with an HMAC blind index (email_hash) so records remain searchable without storing plaintext emails.
  • Shared cPanel hosting: the server runs on Namecheap shared hosting with SSH, MariaDB, and a single-line per-minute cron job.
Architecture 26 to 27 Aug

The platform: durable ingest, queued reconciliation, and a Filament 5 panel

The WordPress SDK posts non-blocking requests ('blocking' => false), so a failed parse or dropped request is never retried by the client. TrackController and DeactivateController resolve the project from its UUID hash, write the raw request to raw_payloads before any interpretation, dispatch ProcessTrackingPayload to the database queue, and return 200 {"success": true} immediately.

In the panel, Account is the Filament 5 tenant (/admin/{account-slug}/...). Because Filament only scopes queries built by its own resources, an Eloquent global scope backed by CurrentAccount stays active so custom widgets and services cannot leak rows across tenants.

Form-encoded booleans
WordPress's http_build_query sends booleans as "1" and "". Standard Laravel boolean validation rejects empty strings, so TrackRequest reads them through explicit accessors.
Uncached project lookup
Caching an Eloquent Project model in the MySQL database cache store stripped the NUL bytes marking protected properties and unserialized as __PHP_Incomplete_Class. Caught during a live run and fixed in 3b44fd7 by querying uncached.
6-hour repeat window
Identical heartbeats within six hours update last_seen_at on sites without inserting a duplicate site_reports row, preventing a misconfigured cron from weighting one site multiple times.
Reactivation on the deactivation row
sites holds current state only. Stamping reactivated_at on the deactivations row lets daily_stats answer how many sites returned on a past date.
The SDK fork 27 Aug

Forking appsero/client and closing two upstream consent holes (P4)

Commit d77d96f forked appsero/client v2.0.4 (MIT) into packages/digi-tracker-client under GPL-2.0-or-later. As documented in packages/digi-tracker-client/README.md, dokan-lite bundles appsero/client unscoped in the global Appsero\ namespace behind if ( ! class_exists( 'Appsero\Client' ) ). Keeping that namespace on a site running Dokan would cause Dokan's unmodified client to load first and silently send our plugin's telemetry to Appsero's servers.

Analytics & mail 27 Aug

Analytics depth, GDPR erasure, and a single-choke-point email layer (P5–P6)

Commits 3550c54, 9d1153f, and 11e74aa added the reproducible demo generator (telemetry:seed-demo --seed), which drives synthetic payloads through SiteReconciler rather than bulk-inserting rows, and telemetry:forget, which deletes a site or email across sites, raw_payloads (which sits outside foreign keys), and any end_users left owning zero sites.

P5 (2042ba9) added the project Reports page: version adoption stacked by percentage share rather than raw count, churn by theme calculated as a rate (excluding themes with fewer than 5 installs), and CSV exports with explicit per-call-site column lists so aggregate-only plugin inventories can never be exported.

P6 (4ae69f7) placed four email surfaces (deactivation auto-responder, deactivation forward to author, weekly Monday digest, and per-project branding) behind a single Mailer service. Because telemetry opt-in is consent to be measured rather than marketed to, the auto-responder fires only when a user typed a comment in the deactivation dialog, once per person per project. Unsubscribe links require no login, support RFC 8058 one-click POST, and store suppressions by HMAC blind index in email_suppressions.

First deploy 27 Aug

Deploying to Namecheap cPanel: four assumptions the server broke

Deploying to space.pluginizelab.com on 27 August (0ae456f and DEPLOY.md section 0a) exposed four differences between local development (MySQL 9 on Herd) and the production Namecheap shared host (CloudLinux, LiteSpeed, MariaDB 11.4.12 behind Cloudflare):

Cloudflare dropped half of POSTs
Because the SDK sends fire-and-forget POSTs, dropped /track requests silently under-counted installs and broke half of Livewire's panel updates. The ingest hostname is therefore DNS-only (A record to 198.54.116.227), and config/proxies.php trusts Cloudflare's IP ranges rather than '*'.
MariaDB defaulted to MyISAM
Migrations failed on utf8mb4 1000-byte key limits. Worse, MyISAM lacks SELECT ... FOR UPDATE row locks and transactions, which would have let overlapping per-minute queue workers send duplicate auto-responders and fired DB::afterCommit() prematurely. config/database.php now pins 'engine' => env('DB_ENGINE', 'InnoDB').
Split document root
cPanel locks the subdomain root to ~/space.pluginizelab.com. deploy/deploy.sh keeps the application outside the web root at ~/digi-tracker, copies public/ into the docroot with rewritten index.php paths, and copies public/build/ to both locations so Blade's @vite manifest check and the web server agree.
PHP 8.3 via CloudLinux handler
/opt/cpanel/ea-php* stopped at 8.2 and selectorctl --domain silently failed to create its CageFS directory. PHP 8.3.33 lived under /opt/alt/php83, pinned per-docroot via AddHandler application/x-httpd-alt-php83___lsphp .php in .htaccess.
wordpress.org 27 to 31 Aug

Putting the public wordpress.org record beside private telemetry

Commits 8d7889e, 5cda5a6, fa34b5f, 938ee2c, and 937bd6c added public repository intelligence. Until released plugins ship with the new SDK, private telemetry reads zero while the plugins on wordpress.org already have years of history.
